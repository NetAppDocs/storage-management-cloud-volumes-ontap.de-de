= Cloud Volumes ONTAP Deployments in Infrastructure Manager konvertieren
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Ab dem 9. Februar 2026 können neue Cloud Volumes ONTAP Deployments in Google Cloud den Google Cloud Infrastructure Manager verwenden. Google stellt den Google Cloud Deployment Manager zugunsten von Infrastructure Manager ein. Die Konvertierung Ihrer bestehenden Cloud Volumes ONTAP Deployments von Deployment Manager zu Infrastructure Manager erfolgt durch manuelles Ausführen des Konvertierungstools. Dieser einmalige Vorgang stellt Ihre Systeme automatisch auf Infrastructure Manager um.

.Informationen zu diesem Vorgang
Das Konvertierungstool ist auf der NetApp Support Site verfügbar und erstellt die folgenden Artefakte:

* Terraform-Artefakte, gespeichert in `conversion_output/deployment_name`.
* Zusammenfassung der Konvertierung, gespeichert in `conversion_output/batch_summary_<deployment_name>_<timestamp>.json`.
* Debug-Protokolle, gespeichert im  `<gcp project number>-<region>-blueprint-config/<cvo name>` Verzeichnis. Sie benötigen diese Protokolle zur Fehlerbehebung. Der  `<gcp project number>-<region>-blueprint-config` Bucket speichert die Terraform-Protokolle.
* Das Cloud Volumes ONTAP Projekt ist das Google Cloud Projekt, in dem Sie Cloud Volumes ONTAP Ressourcen erstellen. Der Console agent und das Cloud Volumes ONTAP System können sich im selben oder in verschiedenen Google Cloud Projekten befinden (projektübergreifende Konfiguration). Bei einer projektübergreifenden Konfiguration können Sie den Console agent in einem Projekt, z. B. Projekt A, einsetzen und Cloud Volumes ONTAP Systeme in einem anderen Projekt, z. B. Projekt B, einsetzen, wenn das service account für den Console agent über die erforderlichen Berechtigungen verfügt.


[CAUTION]
====
Cloud Volumes ONTAP-Systeme, die Infrastructure Manager verwenden, speichern Daten und Datensätze in Google Cloud Storage-Buckets. Für diese Buckets können zusätzliche Kosten anfallen, aber bearbeiten oder löschen Sie die Buckets oder deren Inhalt nicht:

* `gs://netapp-cvo-infrastructure-manager-<project id>`: für ONTAP Versionen und SVM Terraform Vorlagen, die für neue Cloud Volumes ONTAP Deployments verwendet werden. In diesem Bucket enthält der  `dm-to-im-convert` Bucket die Cloud Volumes ONTAP Terraform-Dateien.
* `<gcp project number>-<region>-blueprint-config`: zum Speichern von Google Cloud Terraform-Artefakten.


====
.Bevor Sie beginnen
* Voraussetzung ist, dass Ihr Cloud Volumes ONTAP System Version 9.16.1 oder höher verwendet.
* Es ist sicherzustellen, dass keine der Cloud Volumes ONTAP Ressourcen oder deren Eigenschaften manuell über die Google Cloud Console bearbeitet wurden.
* Es ist sicherzustellen, dass die Google Cloud APIs einschließlich der Google Cloud Quotas API aktiviert sind. Weitere Informationen finden Sie unter https://docs.netapp.com/us-en/console-setup-admin/task-install-agent-google-gcloud.html#step-5-enable-google-cloud-apis["Google Cloud APIs aktivieren"^].
* Voraussetzung ist, dass das Servicekonto für den NetApp Console Agent über alle erforderlichen Berechtigungen verfügt. Weitere Informationen enthält https://docs.netapp.com/us-en/console-setup-admin/reference-permissions-gcp.html#service-account-permissions["Google Cloud-Berechtigungen für den Konsolenagenten"^].
* Wenn sich der Console agent und Cloud Volumes ONTAP in unterschiedlichen Projekten befinden, muss überprüft werden, ob das Dienstkonto für den Console agent im Cloud Volumes ONTAP Projekt über alle erforderlichen Berechtigungen verfügt. Informationen zum Erteilen von Berechtigungen für das Dienstkonto des Console agent für den Zugriff auf andere Projekte in https://docs.netapp.com/us-en/console-setup-admin/task-install-agent-google-console-gcloud.html#console-permissions-google["Für die Verwendung mit dem Agenten ist ein Google Cloud-Dienstkonto zu erstellen."^].
* Bevor Sie mit der Konvertierung beginnen, empfehlen wir Ihnen, einen Snapshot der Root- und Boot-Disks des Cloud Volumes ONTAP Systems zu erstellen.
+
.Für Deployments im privaten oder geschützten Modus müssen folgende zusätzlichen Voraussetzungen erfüllt sein:
[%collapsible]
====
** Stellen Sie sicher, dass Sie die neueste Version des Console-Agenten verwenden. Laden Sie das Produktinstallationsprogramm von der NetApp Support Site herunter und installieren Sie den Agenten anschließend manuell auf Ihrem Host, damit der Agent die Infrastructure Manager APIs nutzen kann.
** Wenn Sie das Tool im privaten Modus ausführen, stellen Sie sicher, dass Sie zusätzlich zu den anderen APIs auch die Cloud Build API aktiviert haben. Informationen dazu finden Sie in https://docs.netapp.com/us-en/console-setup-admin/task-install-agent-google-gcloud.html#step-5-enable-google-cloud-apis["Google Cloud APIs aktivieren"^].
** Voraussetzung ist, dass Sie die Netzwerkkonfigurationen abgeschlossen und den Worker Pool für Deployments im privaten Modus oder in geschützten Umgebungen erstellt haben. Weitere Informationen enthält link:reference-networking-gcp.html#infrastructure-manager-configuration-in-private-mode-or-protected-environments["Infrastructure Manager Konfiguration im privaten Modus oder in geschützten Umgebungen"].


====

[[prepare-the-environment-for-running-the-tool]]
== Bereiten Sie die Umgebung für die Ausführung des Tools vor

Führen Sie diese Schritte aus, bevor Sie das Tool ausführen.

.Schritte
. Erstellen Sie eine Rolle und hängen Sie sie an ein Dienstkonto an:
+
.. Eine YAML-Datei mit den folgenden Berechtigungen ist zu erstellen.
+
[source, cli]
----
title: NetApp Dm TO IM Convert Solution
description: Permissions for the service account associated with the VM where the tool will run.
stage: GA
includedPermissions:
- compute.addresses.get
- compute.disks.get
- compute.forwardingRules.get
- compute.healthChecks.get
- compute.instanceGroups.get
- compute.instances.get
- compute.regionBackendServices.get
- config.deployments.create
- config.deployments.get
- config.deployments.getLock
- config.deployments.lock
- config.deployments.unlock
- config.deployments.update
- config.deployments.delete
- config.deployments.updateState
- config.operations.get
- deploymentmanager.deployments.get
- deploymentmanager.deployments.list
- deploymentmanager.manifests.get
- iam.serviceAccounts.get
- storage.buckets.create
- storage.buckets.get
- storage.objects.create
- storage.objects.delete
- storage.objects.get
- storage.objects.list
----
+
.Zusätzliche Berechtigungen für Deployments im privaten Modus oder geschützte Deployments einschließen
[%collapsible]
====
Wenn Sie das Tool im privaten Modus oder in einer geschützten Umgebung ausführen, sollte die `cloudbuild.workerpools.get` Berechtigung ebenfalls zur YAML-Datei hinzugefügt werden.

====
+
.Zusätzliche Berechtigungen für projektübergreifende Deployments (Console Agent in einem Projekt, Cloud Volumes ONTAP in einem anderen)
[%collapsible]
====
Bei einem projektübergreifenden Deployment erstellen Sie die zuvor genannte YAML-Datei für das Projekt des Console Agent. Sie müssen eine zweite YAML-Datei mit den folgenden Berechtigungen für das Projekt erstellen, in dem sich die Cloud Volumes ONTAP Ressourcen befinden:

[source, cli]
----
title: NetApp Dm TO IM Convert Solution for Cross Project
description: Permissions for the service account associated with the VM where the tool will run for the project where CVO resources resides.
stage: GA
includedPermissions:
- compute.addresses.get
- compute.disks.get
- compute.forwardingRules.get
- compute.healthChecks.get
- compute.instanceGroups.get
- compute.instances.get
- compute.regionBackendServices.get
- deploymentmanager.deployments.get
- deploymentmanager.deployments.list
- deploymentmanager.manifests.get
- resourcemanager.projects.get
----
====
.. In Google Cloud wird im Projekt des Console agent eine benutzerdefinierte Rolle mit den in der YAML-Datei definierten Berechtigungen erstellt. In einer projektübergreifenden Einrichtung wird diese Rolle auch in dem Projekt erstellt, in dem sich die Cloud Volumes ONTAP Ressourcen befinden.
`gcloud iam roles create dmtoim_convert_tool_role --project=PROJECT_ID \
    --file=YAML_FILE_PATH` Weitere Informationen enthält https://cloud.google.com/iam/docs/creating-custom-roles["Erstellen und Verwalten benutzerdefinierter Rollen"^].
.. Weisen Sie die benutzerdefinierte Rolle dem Dienstkonto zu, das Sie zum Erstellen der VM verwenden.
.. Fügen Sie die `roles/iam.serviceAccountUser` Rolle zu diesem Dienstkonto hinzu. Siehe https://docs.cloud.google.com/iam/docs/service-account-overview["Übersicht der Servicekonten"^].
.. Die IAM Service Account Credentials API muss im Projekt aktiviert sein:
+
[source, cli]
----
gcloud services enable iamcredentials.googleapis.com --project=PROJECT_ID
----
.. Das von Ihnen erstellte Dienstkonto muss so konfiguriert sein, dass es sich als das Console Agent-Dienstkonto ausgeben kann. Dazu ist dem von Ihnen erstellten Dienstkonto die `Service Account Token Creator` Rolle zuzuweisen.
+
[source, cli]
----
gcloud iam service-accounts add-iam-policy-binding \
CONSOLE_AGENT_SA@PROJECT_ID.iam.gserviceaccount.com \ --
member="serviceAccount:CONVERT_VM_SA@PROJECT_ID.iam.gserviceaccount.com" \  --
role="roles/iam.serviceAccountTokenCreator" \  --
project=PROJECT_ID
----


. [[create-vm]]Erstellen Sie eine VM mit den folgenden Konfigurationen. Sie führen das Tool auf dieser VM aus.
+
** Maschinentyp: Google Compute Engine machine type e2-medium
** Betriebssystem: Wählen Sie je nach Ihren Anforderungen eines dieser Images aus:
+
*** Ubuntu 26.04 LTS Minimal (ubuntu-2604-resolute-amd64)
*** SUSE Linux Enterprise Server 15 SP7 x86_64


** Netzwerk: Firewall zum Zulassen von HTTP und HTTPS
** Festplattengröße: 20GB
** Sicherheit: Dienstkonten: das von Ihnen erstellte Servicekonto
** Sicherheit: Zugriffsbereich - Zugriffssatz für jede API:
+
*** Cloud Platform: Aktiviert
*** Compute Engine: Nur lesen
*** Speicher: Nur lesen (Standard)
*** Google Cloud Logging (ehemals Stackdriver Logging) API: Write only (default)
*** Stackdriver Monitoring (jetzt Teil von Google Cloud Operations) API: Nur Schreiben (default)
*** Service Management: Schreibgeschützt (Standard)
*** Service Control: Aktiviert (Standard)
*** Google Cloud Trace (ehemals Stackdriver Trace): Nur Schreiben (Standard)




. Stellen Sie über SSH eine Verbindung zur neu erstellten VM her: `gcloud compute ssh dmtoim-convert-executor-vm --zone _<region where VM is deployed>_`
. Laden Sie das Konvertierungstool von der https://mysupport.netapp.com/site/tools/tool-eula/gcp-cvo-dm-to-im-convert-tool/download["NetApp Support Site"^] mit Ihren NSS-Zugangsdaten herunter: `wget <download link from NetApp Support site>`
. Extrahieren der heruntergeladenen Datei: `unzip <downloaded file name>`


[role="tabbed-block"]
====
.Ubuntu
. Laden Sie diese erforderlichen Pakete herunter und installieren Sie sie:
+
** Docker: 28.2.2 build 28.2.2-0ubuntu1 oder höher
** Terraform: 1.14.1 oder höher
** Python: 3.13.7, python3-pip, python3 venv
+
[source, cli]
----
sudo apt-get update
sudo apt-get install python3-pip python3-venv -y
wget -O - https://apt.releases.hashicorp.com/gpg | sudo gpg --dearmor -o /usr/share/keyrings/hashicorp-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] https://apt.releases.hashicorp.com noble main" | sudo tee /etc/apt/sources.list.d/hashicorp.list
sudo apt update && sudo apt install terraform
sudo apt-get install -y docker.io
sudo systemctl start docker
----
+
Google Cloud CLI `gcloud` ist auf der VM vorinstalliert.





.SUSE Linux Enterprise Server
. Python einrichten: `sudo update-alternatives --install /usr/bin/python3 python3 /usr/bin/python3.11 2`
. Installieren Sie pip3, um das Paket zu installieren: `python3.11 -m ensurepip --upgrade`

[[run-the-conversion-tool]]
== Führen Sie das Konvertierungstool aus

Mit diesen Schritten lässt sich das Konvertierungstool sowohl unter Ubuntu als auch unter SUSE Linux Enterprise Server ausführen.

.Schritte
. Fügen Sie den aktuellen Benutzer der Docker-Gruppe hinzu, damit das Tool Docker ohne  `sudo` Privilegien verwenden kann.
+
[source, cli]
----
sudo usermod -aG docker $USER
newgrp docker
----
. Installieren Sie das Konvertierungstool:
+
[source, cli]
----
cd <folder where you extracted the tool>
 ./install.sh
----
+
Dadurch wird das Tool in einer isolierten Umgebung installiert, `dmconvert-venv` und es wird überprüft, ob alle erforderlichen Softwarepakete installiert sind.

. Geben Sie die Umgebung ein, in der das Tool installiert ist: `source dmconvert-venv/bin/activate`
. Die Ausführung des Konvertierungstools erfolgt als `non-sudo` Benutzer. Es ist sicherzustellen, dass dasselbe Dienstkonto wie beim Console agent verwendet wird und dass das Dienstkonto über alle https://docs.netapp.com/us-en/console-setup-admin/reference-permissions-gcp.html#service-account-permissions["Erforderliche Berechtigungen für Google Cloud Infrastructure Manager"^] verfügt.
+
[source, cli]
----
dmconvert \
--cvo-project-id=<the Google Cloud project ID for the Cloud Volumes ONTAP deployment> \
--cvo-name=<Cloud Volumes ONTAP system name> \
--service-account=<the service account attached to the Console agent>
----
+
.Ausführen des Tools in projektübergreifenden Deployments (Console Agent in einem Projekt, Cloud Volumes ONTAP in einem anderen)
[%collapsible]
====
Der `--console-agent-project-id` Parameter gilt, wenn sich Ihr Cloud Volumes ONTAP System in einem anderen Projekt befindet als dem Projekt, in dem sich der Console agent befindet.

[source, cli]
----
dmconvert \
--cvo-project-id=<the Google Cloud project ID for the Cloud Volumes ONTAP deployment> \
--console-agent-project-id=<the Google Cloud project ID for the Console agent> \
--cvo-name=<Cloud Volumes ONTAP system name> \
--service-account=<the service account attached to the Console agent> \
----
====
+
.Ausführung des Tools in privaten oder geschützten Deployments
[%collapsible]
====
Geben Sie den `--worker-pool` Parameter an, um das Tool in Deployments im privaten oder geschützten Modus auszuführen. Weitere Informationen zur Konfiguration des Worker-Pools finden Sie unter link:reference-networking-gcp.html#infrastructure-manager-configuration-in-private-mode-or-protected-environments["Infrastructure Manager Konfiguration im privaten Modus oder in geschützten Umgebungen"].

[source, cli]
----
dmconvert \
--cvo-project-id=<the Google Cloud project ID for the Cloud Volumes ONTAP deployment> \
--cvo-name=<Cloud Volumes ONTAP system name> \
--service-account=<the service account attached to the Console agent> \
--worker-pool=<worker pool name>
----
====


.Nach Abschluss
Das Tool zeigt eine Liste aller Cloud Volumes ONTAP Systeme und SVM-Details an. Nach Abschluss des Vorgangs können Sie die Status aller konvertierten Systeme sehen. Jedes konvertierte System erscheint in der Google Cloud Console unter Infrastructure Manager in einem <system-name-imdeploy> Format. Dieses Format zeigt an, dass die NetApp Console jetzt Infrastructure Manager APIs verwendet, um das jeweilige Cloud Volumes ONTAP System zu managen.


CAUTION: Nach der Konvertierung empfiehlt es sich, das Deployment Objekt für Deployment Manager in der Google Cloud Console nicht zu löschen. Dieses Deployment Objekt enthält Informationen, die Sie möglicherweise benötigen, um das konvertierte System zurückzusetzen.

Wenn Sie die Konvertierung rückgängig machen müssen, müssen Sie dieselbe VM verwenden. Wenn Sie alle Systeme konvertiert haben und nicht zum Deployment Manager zurückkehren müssen, können Sie die VM löschen.



[[roll-back-the-conversion]]
== Die Konvertierung rückgängig machen

Wenn Sie die Konvertierung nicht fortsetzen möchten, können Sie zum Deployment Manager zurückkehren, indem Sie die folgenden Schritte ausführen:

.Schritte
. Führen Sie auf demselben <<create-vm,VM, die Sie zum Ausführen des Tools erstellt haben>> folgenden Befehl aus:
+
[source, cli]
----
dmconvert \
--cvo-project-id=<the Google Cloud project ID for the Cloud Volumes ONTAP deployment> \
--cvo-name=<Cloud Volumes ONTAP system name> \
--service-account=<the service account attached to the Console agent> \
--rollback
----
+
Bei einem projektübergreifenden Deployment ist der  `--console-agent-project-id`Parameter anzugeben:

+
[source, cli]
----
dmconvert \
--cvo-project-id=<the Google Cloud project ID for the Cloud Volumes ONTAP deployment> \
--console-agent-project-id=<the Google Cloud project ID for the Console agent> \
--cvo-name=<Cloud Volumes ONTAP system name> \
--service-account=<the service account attached to the Console agent> \
--rollback
----
. Sie sollten warten, bis das Rollback abgeschlossen ist.
